# The Macro Narrative Engine
## Product Backlog

*This is the master implementation backlog for MNE, effective as of Platform Foundation v1.0. It is not the Product Vision, not an architecture document, and not a roadmap with dates — it is the single source of truth for what should be built next, organized by Epic, with every item scoped to reflect concrete user or platform value. Every future sprint handoff should originate from an item in this document.*

*This document is intentionally living. It should be updated whenever implementation meaningfully changes the state of the product. Status should always reflect verified implementation rather than planned work.*

*Status reflects what is confirmed operational in production as of this writing, based on direct inspection of live run output (`platform_observability`, `source_intelligence`, `narrative_brief`, `event_lifecycle`, and related blocks) and confirmed Codex implementation reports — not merely what has an architecture document.*

## Completed Foundations

The following major platform capabilities are considered complete as part of **Platform Foundation v1.0**. Future contributors should treat these as foundational — generally to be extended, not redesigned:

- **Source Intelligence Platform (SIP)** — Evidence Objects with deterministic IDs, the Source Registry (`config/source_registry.json`), Feed Health, and Freshness Validation, all operational in production.
- **Source Confidence Model** — deterministic evidence-collection confidence persisted under `source_intelligence.source_confidence`, with Admin visibility.
- **Source Trust Layer** — ENI Phase 1 source expansion, ENI Phase 2 network health measurement, Source Confidence, and Source Reliability / Quarantine Tracking are implemented; reliability tracking is recommendation-only with no automatic source status changes.
- **Network Confidence Model** — deterministic synthesis of existing persisted diagnostics (`network_health`, `source_confidence`, `source_reliability.summary`, and `coverage_intelligence`) into `source_intelligence.network_confidence` on live runs, with honest `UNKNOWN` handling for failed-headline or missing-input paths and Admin Evidence Network visibility.
- **Coverage Intelligence (EQE)** — per-narrative evidence breadth, diversity, and concentration measurement, first layer of the Evidence Quality Engine.
- **Evidence Network Initiative foundations** — ENI Phase 1 source coverage repair/expansion and ENI Phase 2 network health measurement, including provider/category rollups, provider concentration, overall network status, persisted `source_intelligence.network_health`, and the Admin Evidence Network section.
- **Narrative Intelligence** — theme/group scoring, taxonomy, Narrative Leadership, Rotation, Pulse, Dynamics, Crowding, Change Summary, Regime Alignment, Breadth Confirmation, and related market/catalyst context engines.
- **Market Context and Expression Layer** — deterministic, descriptive evaluation of narrative expression using persisted market snapshots only. The Narrative Expression Map (`config/market_expression_map.json`) defines primary, secondary, and offset roles for AI / Tech Growth, Energy / Commodities, and Macro Pressure. The layer classifies expression state and breadth, excludes missing or stale instruments from state math, fails closed for unavailable aspirational instruments, and caps primary confirmation at partially confirming when meaningful offset pressure exists. Market Expression appears in the Research Workspace and, when usable context exists, as one concise dashboard sentence; raw instrument details remain secondary. The layer performs no market-data fetching and adds no scoring, taxonomy, replay, expected-return, outcome, prediction, recommendation, or trading logic.
- **Narrative Brief Engine** — deterministic, template-composed, evidence-traceable daily briefs with graceful fallback behavior.
- **Narrative Memory Foundation + Research Workspace Narrative Memory Integration** — deterministic, live-run-based recent memory over meaningful runs only; persists `narrative_memory` on live runs, excludes replay artifacts, classifies theme/group memory states, emits `NARRATIVE_MEMORY` telemetry, and renders an admin-only Narrative Memory section. The standard Research Workspace investigation page now also shows a compact, read-only Recent Memory card for the selected narrative, sourced only from the same persisted `narrative_memory` block, with no recomputation and a calm empty state when memory is unavailable.
- **Narrative History Charts and Lifecycle Visualization** — deterministic narrative history from persisted meaningful live snapshots, with a lifecycle summary and score-history preview on the Narrative Investigation page and a dedicated read-only `/research/{narrative}/history` view. Server-rendered score, attention-share, and rank charts preserve missing dates and narrative absences as uninterpolated gaps. The lifecycle timeline and summary show observed persisted states and context—including recurrence and re-acceleration—without forecasting, replay reads, fetching, rescoring, taxonomy changes, or writes.
- **MNE Explanation Layer / Plain-English Interpretation Improvements** — deterministic, template-based composition from already-persisted fields now leads with plain-English meaning before supporting metrics across the Research Workspace, Narrative History, dashboard, Historical Research, and Historical Comparison. Technical scores, shares, ranks, streaks, counts, deltas, state labels, and engine terminology remain available through progressive disclosure. The layer is not AI-generated, does not predict outcomes, and does not provide trade recommendations.
- **AI Analyst Layer — Path A** — provider-neutral, stateless single-turn Analyst foundation over strictly bounded persisted MNE outputs, with safe context builders for Dashboard, Narrative Investigation, Historical Investigation, and Historical Comparison; deterministic intent classification; pre-provider rejection of unsupported and trade-oriented requests; fail-closed response validation; deterministic Explanation Layer fallback; and explicit Ask Analyst panels on all four supported user-facing surfaces. `DisabledProvider` and `MockProvider` are implemented, but no real paid/network provider is connected and no paid API calls are enabled. ## How to Read This Backlog

**Status is tracked at the Epic level**, in each Epic's "Current status" line — it describes what is verifiably built today, per the verification standard stated above. Status is deliberately not tracked per item: most unbuilt items would simply repeat "not started," and Epic-level status plus each item's Dependencies column together tell the full readiness story without that noise.

**Status vocabulary (Epic level):**
- **Implemented / Substantially Implemented** — confirmed operational in production output or by an explicit Codex implementation report.
- **In Progress** — implementation has begun or was partially confirmed.
- **Architecture complete, not started** — a canonical architecture document exists; no implementation has begun.
- **Not started** — neither implementation nor (in some cases) detailed architecture exists yet.

**Priority is tracked at both levels.** Each Epic carries an epic-level Priority describing how urgently the Epic as a whole deserves attention right now; each Backlog Item additionally carries its own Priority (`Critical` / `High` / `Medium` / `Low` / `Future`), since a single Epic can contain both work that's ready today and work that's correctly deferred.

**One clarification on how Priority relates to sequencing:** item-level Priority describes the *importance/severity* of the item itself; the Recommended Implementation Order at the end of this document describes *sequencing*, which weighs importance against value-per-effort. These are different axes — an item can be genuinely Critical in severity (e.g., a degraded data source) while still being correctly sequenced behind work that unlocks more user value per unit of effort. When the two appear to disagree, the Implementation Order governs what gets built next; item Priority governs how seriously the item is treated when its turn comes.

## Epic 1 — Research Workspace / User Experience

**Goal:** Give users an actual place to investigate a narrative in depth, using intelligence MNE already produces.

**Why it matters:** This is currently MNE's single biggest gap between backend capability and user-visible value. SIP, the Evidence Quality Engine, the Event Lifecycle Engine, and the Narrative Brief Engine are all fully operational — but none of that reaches a user beyond the flat dashboard. A working Research Workspace converts already-built intelligence into a usable product for the first time.

## Epic 2 — Historical Replay / Historical Backfill

**Goal:** Let MNE reconstruct what it would have concluded on any past date, using only evidence that existed at the time.

**Why it matters:** This is the foundation everything in Narrative Memory depends on, and it's what eventually lets the Research Workspace answer "how did we get here," not just "what's happening now."

**Current status:** **Historical Replay Foundation, Historical Replay Admin Console, User-Facing Historical Research UX, User-Facing Historical Comparison UX, Admin Replay Multi-Select UI, Historical Research Workspace Integration, four official-source backfill connectors, Historical Backfill Replay Integration, Multiple Backfill IDs Per Replay, replay-level Coverage Intelligence, Historical Comparison View, Admin UI Backfill Selection, and the Automatic Backfill-to-Replay Workflow are implemented.** Users can select and inspect one completed historical reconstruction or compare two completed periods through read-only `/history` routes without seeing admin, backfill, workflow, or replay internals. Historical comparison is available to normal users in read-only form and uses completed replay artifacts only. Historical replay generation and backfill execution remain admin-only. Historical backfills can be triggered from `/admin`, multiple backfills can be included in one replay, and the Admin Replay Multi-Select UI is implemented. The guided Build Historical Replay workflow lets an admin select one or more supported sources, run their backfills sequentially in deterministic source order, review `COMPLETE`, `EMPTY`, and `FAILED` outcomes—including partial failures—and explicitly launch one combined replay using only replay-ready backfill IDs. Replay does not start automatically. Confirmation reloads and validates the trusted persisted workflow manifest before using the existing multi-backfill replay engine; duplicate confirmation submissions and confirmation-page refreshes do not rerun replay, and page refreshes do not rerun backfills. Workflow manifests persist under `MNE_DATA_DIR/historical_workflows/{workflow_id}/manifest.json`. Workflow state, backfill artifacts, replay artifacts, and live results remain separate persisted concerns and explicit workflow stages.

Core replay cutoff, temporal-integrity, provenance, deterministic deduplication, isolated persistence, no-live-fetch behavior, multi-backfill support, and replay-level coverage reporting remain implemented as previously documented. The reconstruction workflow is admin-only and synchronous: no background jobs, queues, or concurrent backfill execution exist; source selection is manual rather than automatic; and users cannot run backfills or replays. The unified historical request workflow and public/user-triggered reconstruction requests are not implemented. Historical news archive integration and full historical market reconstruction remain future work. Authentication, accounts, and server-side entitlement enforcement are implemented; billing-provider integration and paid purchase flows remain future product/security work.

**Dependencies:** The Evidence Object schema and deterministic `evidence_id` scheme (SIP, done) are the direct technical foundation. The four implemented official-source connectors provide replay-ready policy, inflation, growth, and energy evidence. Historical Backfill Replay Integration and Multiple Backfill IDs Per Replay consume explicitly requested backfilled evidence, while the guided admin workflow coordinates source selection, sequential backfill execution, partial-result review, manifest validation, and explicit combined-replay confirmation. Authentication, centralized authorization, and admin route protection are implemented. Background job execution, concurrency, automatic source selection, a unified user historical request workflow, public/user-triggered reconstruction, historical news archive integration, additional connectors, and advanced historical visualizations remain future work.

## Epic 3 — Narrative Memory

**Why it matters:** Without this, MNE's intelligence resets every day. This is what turns individual runs into an actual accumulated history.

**Current status:** **Narrative Memory Foundation, Admin Narrative Memory, Research Workspace Narrative Memory Integration, Narrative History Charts and Lifecycle Visualization, the deterministic MNE Explanation Layer, and Historical-to-Current Narrative Connection are implemented.** `mne/narrative_memory.py` builds deterministic memory from recent meaningful live runs only, persists `narrative_memory` on live runs, excludes replay artifacts as inputs, and excludes or handles failed/no-signal runs according to the meaningful-run policy. ## Recommended Implementation Order

Following the guiding philosophy — **build the smallest amount of software that creates the largest increase in user value** — and respecting every dependency called out above:

The next likely sequence is:

1. **Entitlements and usage limits** — implement server-enforced feature and usage boundaries against the approved packaging; paid entitlement enforcement does not exist today.
2. **Billing provider integration** — connect commercial payment state to the account and entitlement architecture.
3. **Plan-aware UI and upgrade flows** — explain current access, limits, and upgrade paths without implying unavailable paid capabilities.
4. **Paid beta lifecycle testing** — verify signup, plan changes, billing-state transitions, entitlement behavior, cancellation, and recovery before broader release.
5. **Email delivery / self-service reset** — add email verification and user-initiated password recovery on top of the implemented single-use reset-token foundation.
6. **Production hardening** — harden database, session, cookie, deployment, monitoring, backup, and operational behavior for production use.

**Sequence status annotation (July 2026):** Product packaging planning and Authentication and Account Architecture are complete. The ratified Free / Pro / later Team structure and server-controlled plan assignments do not constitute billing or paid entitlement enforcement. Email verification, self-service email reset, Team workspaces, social login/SSO, and full account-management administration also remain future work.

The Personalization and Alerts Foundation, Authentication and Account Architecture, AI Analyst Path A foundation, deterministic MNE Explanation Layer, plain-English-first summaries, progressive disclosure of technical metrics, Narrative History Charts and Lifecycle Visualization, Historical-to-Current Narrative Connection, and Market Context and Expression Layer are implemented and therefore removed from future sequencing. Broader market coverage for currently unavailable mapped instruments, historical market-price context, narrative-versus-market outcome analysis, Market Expression Map expansion, cross-narrative comparison charts, longer configurable history windows, similar-period matching, and additional advanced historical visualizations remain future work. External alert delivery and background evaluation remain future work. Backtesting is not implemented. Recommendations, predictions, and trade alerts or signals remain explicitly out of scope. Public/user-triggered reconstruction is not implied by the implemented read-only Historical Research UX.

**Items that must not begin out of order, restated for emphasis:**
- **Epic 3 (Narrative Memory)** foundation work, Research Workspace Narrative Memory Integration, and single-narrative History Charts and Lifecycle Visualization are complete for persisted meaningful live history. Future replay-timeline memory should wait until **Epic 2 (Historical Replay)** and the relevant product surface are mature enough for the specific memory work. A standalone user-facing Narrative Memory dashboard and cross-narrative comparison charts remain future work pending deliberate UX scoping.
- Future expansion in **Epic 4 (AI Experience)** remains grounded in the stable deterministic outputs and safety boundaries used by the implemented Path A foundation.
- **Epic 7's non-headline connectors** do not begin before the current, headline-only Evidence Object architecture has been proven stable in production for a meaningful period — consistent with SIP's own original phased build discipline.

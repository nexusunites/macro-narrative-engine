# The Macro Narrative Engine
## Product Backlog

*This is the master implementation backlog for MNE, effective as of Platform Foundation v1.0. It is not the Product Vision, not an architecture document, and not a roadmap with dates — it is the single source of truth for what should be built next, organized by Epic, with every item scoped to reflect concrete user or platform value. Every future sprint handoff should originate from an item in this document.*

*This document is intentionally living. It should be updated whenever implementation meaningfully changes the state of the product. Status should always reflect verified implementation rather than planned work.*

*Status reflects what is confirmed operational in production as of this writing, based on direct inspection of live run output (`platform_observability`, `source_intelligence`, `narrative_brief`, `event_lifecycle`, and related blocks) and confirmed Codex implementation reports — not merely what has an architecture document.*

## Completed Foundations

The following major platform capabilities are considered complete as part of **Platform Foundation v1.0**. Future contributors should treat these as foundational — generally to be extended, not redesigned:

- **Source Intelligence Platform (SIP)** — Evidence Objects with deterministic IDs, the Source Registry (`config/source_registry.json`), Feed Health, and Freshness Validation, all operational in production.
- **Source Confidence Model** — deterministic evidence-collection confidence persisted under `source_intelligence.source_confidence`, with Admin visibility.
- **Source Trust Layer** — ENI Phase 1 source expansion, ENI Phase 2 network health measurement, Source Confidence, and Source Reliability / Quarantine Tracking are implemented; reliability tracking is recommendation-only with no automatic source status changes.
- **Network Confidence Model** — deterministic synthesis of existing persisted diagnostics (`network_health`, `source_confidence`, `source_reliability.summary`, and `coverage_intelligence`) into `source_intelligence.network_confidence` on live runs, with honest `UNKNOWN` handling for failed-headline or missing-input paths and Admin Evidence Network visibility.
- **Coverage Intelligence (EQE)** — per-narrative evidence breadth, diversity, and concentration measurement, first layer of the Evidence Quality Engine.
- **Evidence Network Initiative foundations** — ENI Phase 1 source coverage repair/expansion and ENI Phase 2 network health measurement, including provider/category rollups, provider concentration, overall network status, persisted `source_intelligence.network_health`, and the Admin Evidence Network section.
- **Narrative Intelligence** — theme/group scoring, taxonomy, Narrative Leadership, Rotation, Pulse, Dynamics, Crowding, Change Summary, Regime Alignment, Breadth Confirmation, and related market/catalyst context engines.
- **Narrative Brief Engine** — deterministic, template-composed, evidence-traceable daily briefs with graceful fallback behavior.
- **Narrative Memory Foundation + Research Workspace Narrative Memory Integration** — deterministic, live-run-based recent memory over meaningful runs only; persists `narrative_memory` on live runs, excludes replay artifacts, classifies theme/group memory states, emits `NARRATIVE_MEMORY` telemetry, and renders an admin-only Narrative Memory section. The standard Research Workspace investigation page now also shows a compact, read-only Recent Memory card for the selected narrative, sourced only from the same persisted `narrative_memory` block, with no recomputation and a calm empty state when memory is unavailable.
- **Event Lifecycle Engine** — deterministic catalyst phase awareness.
- **Platform Observability (POL)** — per-stage pipeline telemetry, run metadata, and engine version reporting.
- **Configuration Portability** — environment-driven, cross-platform data directory resolution with no import-time filesystem side effects.
- **Evidence Diagnostics** — accepted-evidence persistence (capped at 500 entries with an explicit truncation flag), the evidence funnel summary, the zero-match warning, and the healthy-but-severely-stale source flag.
- **Operations Center MVP + Network Confidence Integration** — render-time, admin-only operational summary using existing persisted signals, with component summaries for Configuration, Pipeline / Platform Observability, Evidence Network, Network Confidence, Source Confidence, Source Reliability, Coverage Intelligence, and Freshness / Feed Health.
- **Dashboard Data Quality Banner / Trust Summary** — compact user-facing evidence-quality summary in the dashboard, built from existing persisted signals only, now using persisted Network Confidence as an input when present and known, without exposing admin diagnostics or changing scoring, sources, persistence, or admin behavior.
- **Research Workspace MVP + UX Polish + Evidence Reader Panel** — `/research` selector, narrative investigation page, dashboard entry-point wiring, admin-gated observability reference, paced investigation zones, readable evidence display, neutral coverage explanation, calm event lifecycle empty state, selectable Supporting Evidence cards, headline-level Evidence Reader side panel, original article access when available, calm unavailable state for missing URLs, and admin boundary are implemented.
- **Historical Replay Foundation + Admin Console + Historical Research Workspace Integration** — replay request creation, historical evidence selection with publication and knowledge-boundary cutoffs, ineligible evidence exclusion, accepted eligible evidence inclusion, deterministic theme/group replay wrapper, isolated replay persistence under configured replay storage, replay metadata, config portability, no-live-fetch replay behavior, determinism tests, cross-validation against known live run scores from the same accepted evidence, the admin-only `/admin` replay trigger/summary console, and the admin-gated replay research view are implemented and verified.
- **Fed/FOMC Historical Backfill MVP** — historical backfill request plumbing, Fed/FOMC post-meeting statement connector, normalized replay-ready historical evidence generation, isolated historical-evidence storage, manifest/evidence persistence, and `HISTORICAL_BACKFILL` evidence-origin tagging are implemented and verified without modifying live results or replay artifacts.
- **BLS Inflation Historical Backfill MVP** — the second official-source historical connector parses BLS CPI/inflation release archive records, produces normalized replay-ready evidence plus `manifest.json` and `evidence.json` under the isolated historical-evidence namespace, and remains separate from live collection and replay artifacts until explicitly included by `backfill_id`.
- **BEA GDP/PCE Historical Backfill MVP** — the third official-source historical connector parses official BEA GDP and Personal Income and Outlays / PCE release records, produces normalized replay-ready evidence plus `manifest.json` and `evidence.json` under the isolated historical-evidence namespace, and remains separate from live collection and replay artifacts until explicitly included by `backfill_id`.
- **EIA Energy Historical Backfill MVP** — the fourth official-source historical connector parses official Weekly Petroleum Status Report and Natural Gas Storage archive release metadata, produces normalized replay-ready evidence plus `manifest.json` and `evidence.json` under the isolated historical-evidence namespace, and remains separate from live collection and replay artifacts until explicitly included by `backfill_id`.
- **Historical Backfill Replay Integration** — Historical Replay can optionally include already-created backfilled evidence by `backfill_id`, selected with the replay evidence cutoff, deduped against live persisted evidence by `evidence_id` with live evidence winning collisions, and recorded in replay metadata without modifying live results, backfill files, or fetching from sources during replay.
- **Historical Comparison View** — admin-only comparison of two persisted replay artifacts from `MNE_DATA_DIR/replays/`, with replay artifact comparison, theme/group deltas, deterministic dominance-change rendering, evidence-base comparison, and backfill provenance rendering when present; it does not trigger replay execution, historical backfill, RSS/live fetches, live-result fallback reads, or artifact/result mutation.

This is a summary for orientation only — each system's canonical reference is its own architecture document in this repository.

## How to Read This Backlog

**Status is tracked at the Epic level**, in each Epic's "Current status" line — it describes what is verifiably built today, per the verification standard stated above. Status is deliberately not tracked per item: most unbuilt items would simply repeat "not started," and Epic-level status plus each item's Dependencies column together tell the full readiness story without that noise.

**Status vocabulary (Epic level):**
- **Implemented / Substantially Implemented** — confirmed operational in production output or by an explicit Codex implementation report.
- **In Progress** — implementation has begun or was partially confirmed.
- **Architecture complete, not started** — a canonical architecture document exists; no implementation has begun.
- **Not started** — neither implementation nor (in some cases) detailed architecture exists yet.

**Priority is tracked at both levels.** Each Epic carries an epic-level Priority describing how urgently the Epic as a whole deserves attention right now; each Backlog Item additionally carries its own Priority (`Critical` / `High` / `Medium` / `Low` / `Future`), since a single Epic can contain both work that's ready today and work that's correctly deferred.

**One clarification on how Priority relates to sequencing:** item-level Priority describes the *importance/severity* of the item itself; the Recommended Implementation Order at the end of this document describes *sequencing*, which weighs importance against value-per-effort. These are different axes — an item can be genuinely Critical in severity (e.g., a degraded data source) while still being correctly sequenced behind work that unlocks more user value per unit of effort. When the two appear to disagree, the Implementation Order governs what gets built next; item Priority governs how seriously the item is treated when its turn comes.

## Epic 1 — Research Workspace

**Goal:** Give users an actual place to investigate a narrative in depth, using intelligence MNE already produces.

**Why it matters:** This is currently MNE's single biggest gap between backend capability and user-visible value. SIP, the Evidence Quality Engine, the Event Lifecycle Engine, and the Narrative Brief Engine are all fully operational — but none of that reaches a user beyond the flat dashboard. A working Research Workspace converts already-built intelligence into a usable product for the first time.

**Current status:** **Implemented.** Research Workspace MVP, UX polish, Evidence Reader Panel, and Narrative Memory integration are confirmed implemented. The `/research` selector is purpose-led and card-based; the investigation page is organized into four paced zones (Snapshot, Explanation, Evidence, Research Entry Points); Supporting Evidence is more readable and selectable; selected evidence opens in a side panel with deterministic, field-bound headline-level explanation; original article access remains available when a URL exists; missing URLs show a calm unavailable state; coverage explanation uses neutral breadth-not-quality language; Event Lifecycle empty state is calm; dashboard links use investigation-oriented wording; and admin-only diagnostics remain gated. The Narrative Memory card is implemented for live narrative investigations: the standard Research Workspace now shows recent memory context (state, appearances, dominance count, streak, momentum, score/share change, and a plain-language summary) for the selected narrative when a matching persisted memory record is available, sourced only from the selected run's existing `narrative_memory` block with no recomputation, no result-file scanning, and no replay-artifact reads. Historical context integration exists only in the admin-gated replay research form; standard user Research Workspace historical mode is not implemented. Full article ingestion and full article summarization are not implemented.

**Dependencies:** None remaining. Every engine this Epic consumes (SIP, Narrative Intelligence, EQE, Event Lifecycle, Narrative Brief) is already implemented and confirmed live.

## Epic 2 — Historical Replay / Historical Backfill

**Goal:** Let MNE reconstruct what it would have concluded on any past date, using only evidence that existed at the time.

**Why it matters:** This is the foundation everything in Narrative Memory depends on, and it's what eventually lets the Research Workspace answer "how did we get here," not just "what's happening now."

**Current status:** **Historical Replay Foundation implemented and verified; Historical Replay Admin Console implemented; Historical Research Workspace Integration implemented; Historical Evidence Backfill Architecture complete; Fed/FOMC Historical Backfill MVP implemented; BLS Inflation Historical Backfill MVP implemented; BEA GDP/PCE Historical Backfill MVP implemented; EIA Energy Historical Backfill MVP implemented; Historical Backfill Replay Integration implemented; Historical Comparison View implemented.** Core replay request creation, evidence cutoff using publication and knowledge-boundary rules, rejected/stale/duplicate/unknown evidence exclusion, accepted eligible evidence inclusion, isolated replay persistence under configured replay storage, replay metadata (`cutoff`, evidence selection rule, and `future_evidence_excluded`), determinism verification, no-live-RSS-fetch replay behavior, config portability for replay storage, and cross-validation against known live run scores from the same accepted evidence are implemented. Admin can trigger deterministic replays from `/admin`, inspect compact replay summaries, view warnings, artifact filename/path, and recent replay history; admins can now open valid completed replay artifacts in a research-style historical investigation view and compare two persisted replay artifacts from the admin-only Historical Comparison View. That view reads only from `MNE_DATA_DIR/replays/`, rejects path traversal and invalid replay IDs, does not read live results as fallback, does not trigger replay execution, does not trigger historical backfill, does not fetch RSS/live data, and does not modify replay artifacts or live results. Historical Comparison computes replay artifact comparison, theme/group deltas from persisted replay scores only, NEW/DROPPED classification from zero-vs-nonzero values rather than key presence, deterministic dominance-change comparison, evidence-base comparison, and backfill provenance comparison when present, including replay artifacts that contain backfilled evidence. User dashboard and standard `/research` do not expose comparison UI. Replay artifacts remain isolated from live results. Historical backfill now supports at least four official-source categories: Fed/FOMC monetary policy communications, BLS CPI/inflation releases, BEA GDP/PCE growth and inflation-adjacent releases, and EIA energy/commodities releases. All four connectors produce normalized replay-ready evidence stored separately from live results and replay artifacts under `MNE_DATA_DIR/historical_evidence/{backfill_id}/` with `manifest.json`, `evidence.json`, `backfill_id`, connector metadata, and `evidence_origin = HISTORICAL_BACKFILL`. Historical Replay can consume already-created Fed/FOMC, BLS CPI, BEA GDP/PCE, or EIA Energy backfilled evidence when explicitly requested through optional `backfill_id` and `include_backfilled_evidence` replay request fields or the CLI's `--backfill-id` and `--include-backfilled` flags. Backfilled evidence is selected using `published_at <= evidence_cutoff`, deduped with live persisted evidence by `evidence_id`, and live evidence wins collisions. Replay metadata records `backfilled_evidence_included`, `backfill_ids_used`, `live_persisted_evidence_included`, `evidence_sources_used`, `backfilled_evidence_count`, `live_evidence_count`, and `total_evidence_count`. Backfilled evidence appears in replay accepted evidence with `evidence_origin = HISTORICAL_BACKFILL`; no live results or backfill evidence files are modified, and no network/source fetching occurs during replay. Historical Research and Historical Comparison can render and compare replay artifacts containing Fed/FOMC, BLS CPI, BEA GDP/PCE, or EIA Energy backfilled evidence. Backfilled evidence remains separate from live results and replays until explicitly included in a replay. Full historical market reconstruction is not complete. BLS PPI, BLS Employment Situation, additional BEA/EIA connectors if needed, historical news archive integration, user-facing replay UI, standard `/research` historical mode, public/user-facing Historical Comparison UI, historical comparison charts, admin UI backfill selection, multiple backfill IDs per replay, Coverage Intelligence support for backfilled evidence, and broader public historical UI remain future work. Full EIA API ingestion is not implemented.

**Dependencies:** The Evidence Object schema and deterministic `evidence_id` scheme (SIP, done) are the direct technical foundation. The Fed/FOMC Historical Backfill MVP provides the first historical source connector, the BLS Inflation Historical Backfill MVP provides the second official-source connector and replay-ready CPI evidence, the BEA GDP/PCE Historical Backfill MVP provides the third official-source connector and replay-ready growth and inflation-adjacent evidence, and the EIA Energy Historical Backfill MVP provides the fourth official-source connector and replay-ready energy/commodities evidence. Historical Backfill Replay Integration consumes explicitly requested already-created backfilled evidence, and the admin-only Historical Comparison View compares persisted replay artifacts that may include it. BLS PPI, BLS Employment Situation, additional BEA/EIA connectors if needed, historical news archive integration, admin UI backfill selection, multiple backfill IDs per replay, Coverage Intelligence support for backfilled evidence, historical comparison charts, and public historical comparison/research surfaces remain future work.

**Epic priority:** **High** (foundational, but sequenced deliberately after Research Workspace has a working live-data experience to extend)

## Recommended Implementation Order

Following the guiding philosophy — **build the smallest amount of software that creates the largest increase in user value** — and respecting every dependency called out above:

**Phase 1 — Immediate.** The highest-leverage work available right now, sequenced by the size of the user-visible value each unlocks:
1. Epic 6: remaining dashboard trust fixes — hero sentence bug, human-readable run selector, and trend-label verification (all Low complexity, immediate trust wins). The Dashboard Data Quality Banner / Trust Summary is already complete.

**Phase 2 — Near-term.** Once the dashboard's remaining quick fixes are in:
2. Epic 2 / Epic 8: Admin UI backfill selection, if desired — add operator UI for choosing available backfills during replay. The current implementation supports explicit request/CLI inclusion, but admin UI selection is not implemented.
3. Epic 2 / Epic 7: Multiple backfill IDs per replay — define selection and merge semantics so a replay can combine several historical evidence packages.
4. Epic 2 / Epic 7: Coverage Intelligence support for backfilled evidence — extend coverage/completeness language for backfill-backed replay contexts. Coverage Intelligence does not fully support backfilled evidence yet.
5. Epic 1 / Epic 2: User-facing historical comparison/research UX — build public historical comparison and research surfaces only after sufficient historical source coverage and user-facing historical research behavior are deliberately scoped. Public historical UI is not implemented.
